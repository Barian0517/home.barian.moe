# 個人官網經驗區塊內容擴充計畫

本次更新旨在將最新的 **Android 底層漏洞研究、Root 玩機生態（KernelSU / Vector / LSPosed Hook）、Linux 內核調校**，以及 **SidebarMod** 與 **Termux + Agy CLI 系統級自動化** 實戰經驗完整納入個人官網的經驗展示頁面。所有新增項目將嚴格沿用既有排版結構、暗色主題視覺風格、動畫與雙星號粗體語法，並完整保留所有既有卡片內容。

> [!IMPORTANT]

- **已確認決策 1（技術專長 — 僅新增不改動既有卡片）**：不修改現有的「網路安全與逆向工程」或其他任何既有專長卡片；改以新增獨立專長卡片「Android 底層開發與系統調校 (Android Internals & Hooking)」承載全部新內容，並將原本欲補充的「Android 漏洞與免解鎖提權架構」完整收錄於該新卡片中，確保零內容遺失且不破壞原有區塊。
- **已確認決策 2（代表性專案排序）**：將新增的「SidebarMod 全域系統輔助與溫控調校工具」與「Termux + Agy CLI 移動端系統級自動化架構」兩項專案卡片置於**代表性專案列表的最上方**，讓訪客第一時間看見最新核心成果，原有專案卡片維持原樣不變。

- **建議預設（核心技能清單更新方式）**：於「核心技能清單」的既有技能總覽中，補齊 `Kotlin`、`Java`、`Android (AOSP / ColorOS Internals)`、`KernelSU`、`LSPosed / Xposed (Vector)`、`Android Framework Hook` 與 `Termux` 等關鍵字，維持單一總覽清單便於訪客一次檢視。若希望此區塊也改為「不改動原卡片、另增一張 Android 技能卡片」，請於審閱時告知。

## 1. 總覽與核心概念

- **核心展示目標**：在既有個人履歷／經歷頁面中，系統化呈現行動端底層研究（Bootloader 免解鎖提權、KernelSU、Vector / LSPosed Hook）、系統層輔助開發（SidebarMod）與行動端本機自動化代理（Termux + Agy CLI）三大最新技術主軸。
- **目標受眾**：瀏覽個人官網的技術同好、開源社群成員、潛在合作夥伴或技術招募人員，期望快速理解開發者在虛擬化、全端、遊戲模組以外的系統底層與行動端自動化深度實力。
- **核心價值**：透過「不改動既有區塊、新增專屬區域並置頂最新代表專案」的編排，讓最新技術亮點具備最高能見度，同時維持過往專案履歷的完整性與一致性。

## 2. 使用者體驗與視覺設計

- **主要瀏覽流程**：
  1. 訪客進入經驗頁面，預設顯示「技術專長」，捲動至底層技術區段時可閱讀新增的「Android 底層開發與系統調校」專長卡片，完整涵蓋免解鎖提權漏洞研究、Xposed/Vector 框架 Hook、高通溫控逆向與原生系統應用開發。
  2. 切換至「代表性專案經驗」後，頁面頂部立即呈現「SidebarMod」與「Termux + Agy CLI」兩張最新代表作；點擊左側（行動端為上方橫向）篩選器時：
     - 選擇「應用與系統開發」可篩選出 `SidebarMod`（連同既有的 `sakura player`、`Android 系統逆向降級實踐`）。
     - 選擇「AI 自動化」可篩選出 `Termux + Agy CLI`（連同既有的 `音遊自動通關`、`自動答題系統`）。
  3. 切換至「核心技能清單」，即可在統一的技能分類中檢視完整升級後的技術棧關鍵字。
- **視覺識別與風格延續**：
  - *整體基調*：完全維持現有的極簡暗黑科技風格（背景 `#050505`、卡片微透玻璃層 `bg-white/[0.02]` 與細邊框 `border-white/5`、懸停微亮 `hover:bg-white/[0.04]`）。
  - *字體與層級*：標題沿用 `Zen Maru Gothic` 粗體灰白字（`text-gray-100`），內文延續 `leading-relaxed` 段落間距，並透過既有的雙星號語法（`**粗體標題**：內文`）自動渲染高亮小標（`text-gray-200 font-medium`），確保新舊卡片視覺完全一致。
  - *互動回饋與動效*：無縫繼承既有的分類切換淡入上浮轉場、黏性頁首與側邊篩選按鈕狀態高亮，不引入額外雜訊元素。

## 3. 關鍵產品決策與權衡

- **決策 1：整合「Android 漏洞與免解鎖提權架構」至新增專長卡片，而非修改既有卡片**
  - *採用方案*：將原計畫寫入「網路安全與逆向工程」卡片的漏洞與 Root 架構描述，移入新增的「Android 底層開發與系統調校」卡片作為第一條核心條目，其後銜接 Xposed/Vector 框架、Linux 內核溫控逆向與原生系統應用開發。
  - *原因*：嚴格遵守使用者「不要修改既有區塊」的要求，同時讓四條 Android 底層技術由淺入深（漏洞提權 → 框架 Hook → 內核溫控 → 原生應用落地）呈現高度連貫的敘事結構。
  - *曾考慮的替代方案*：拆分為兩張獨立新卡片（一張漏洞提權、一張系統開發）；但因漏洞提權條目僅一段，單獨成卡視覺密度偏低，合併於同一張 Android 底層專長卡排版最為均衡。

- **決策 2：將兩項新專案置於代表性專案列表最上方**
  - *採用方案*：在代表性專案資料陣列開頭依序插入 `sidebar-mod` 與 `termux-agy-agent`，其後完整保留原有十項專案與原排序。
  - *原因*：符合使用者確認的排序偏好，確保最新、技術深度最高的代表性成果在「全部分類」預設視圖中優先曝光。

- **決策 3：維持現有專案篩選器鍵值，將 Termux + Agy CLI 對應至 `ai` 分類**
  - *採用方案*：`sidebar-mod` 使用 `projectType: 'app'`，`termux-agy-agent` 使用 `projectType: 'ai'`，不改動既有 `ExperienceItem` 型別定義。
  - *原因*：完全相容現有側邊欄篩選邏輯與 TypeScript 型別檢查，不會影響既有卡片與篩選行為。

### 資料模型與狀態策略

- **資料結構維持相容**：完全沿用既有的 `Category`、`ExperienceItem` 介面與 `PROJECT_TYPES` 篩選設定，不變更任何欄位型別或外部依賴。
- **純靜態宣告式更新**：所有更新皆屬於頁面內的結構化陣列資料，透過既有的雙星號正則解析器（`text.split(/(\*\*.*?\*\*)/g)`）自動轉換為高亮粗體標題與內文段落。

### 互動元件與狀態對應

- **分類切換 (`activeCategory`)**：點擊導覽列或行動端下拉目錄時切換顯示區塊，並自動重設 `selectedProjectType` 為 `'all'`，確保切換至代表性專案時立即看到置頂的兩項新專案。
- **專案篩選 (`selectedProjectType`)**：點選「應用與系統開發」即時過濾顯示 `sidebar-mod` 與既有 `app` 類型專案；點選「AI 自動化」即時過濾顯示 `termux-agy-agent` 與既有 `ai` 類型專案。
- **驗證策略**：完成更新後執行 TypeScript 編譯建置與語法檢查，確認零型別錯誤且不影響任何既有頁面與動畫元件。
